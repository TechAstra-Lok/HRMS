## Contributing to Enterprise HRMS

We appreciate your interest in contributing to the Enterprise HRMS project! This document provides guidelines and instructions for contributing.

### Code of Conduct

- Be respectful and inclusive
- Provide constructive feedback
- Report issues responsibly
- Follow coding standards

### Getting Started

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/your-feature`
3. Make your changes
4. Commit with clear messages: `git commit -m 'Add feature: ...'`
5. Push to your fork: `git push origin feature/your-feature`
6. Create a Pull Request

### Coding Standards

#### Python
- Follow PEP 8
- Use type hints
- Write docstrings
- Format with Black (line length: 120)
- Run linters before submitting

#### JavaScript
- Use ES6+ syntax
- Add JSDoc comments
- Use meaningful variable names
- Test across browsers

#### SQL
- Use clear table and column names
- Add indexes for frequently queried fields
- Document complex queries

### Testing

- Write tests for new features
- Maintain >80% code coverage
- Test edge cases and error scenarios
- Include integration tests

### Pull Request Process

1. Update documentation
2. Add/update tests
3. Run full test suite
4. Ensure no breaking changes
5. Provide clear PR description

### Reporting Issues

- Use issue templates
- Provide clear reproduction steps
- Include environment details
- Attach relevant logs

### Development Setup

See README.md for development environment setup instructions.

### Security

- Report security issues privately
- Don't create public issues for vulnerabilities
- Allow 90 days for fixes before disclosure

Thank you for contributing!
